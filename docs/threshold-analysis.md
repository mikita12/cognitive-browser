# Reflex Core Confidence Threshold Calibration & Analysis

This document details the empirical trade-offs of varying the Reflex Core confidence threshold (`REFLEX_CONFIDENCE_THRESHOLD`) across both offline labeled evaluation sets and live interaction steps.

The table below reflects evaluation using `benchmarks/threshold_sweep.py` executed on NVIDIA GeForce RTX 4070 Ti (CUDA) using the `cross-encoder/nli-deberta-v3-small` checkpoint.

> **Sample Size & Statistical Limitation Notice:**
> The current evaluation corpus comprises **13 labeled offline task scenarios** (10 resolvable interactive steps, 3 impossible/unmatched adversarial cases) and **32 live interaction steps** from the 15-case benchmark. Because the sample size is modest ($n = 13$ offline, $n = 32$ live), these numbers should be interpreted as indicative calibration guidance rather than a universal guarantee.
>

## Architectural Trade-Off Analysis

Configuring the threshold represents an operational trade-off between autonomous execution speed and LLM escalation cost:

1. **Lower Thresholds (`< 0.50`)**:
   - Maximizes autonomous routing: Reflex handles virtually all steps locally at ~25 ms latency without calling external LLMs.
   - Risk: Ambiguous or misleading interactive elements with weak entailment may be triggered without human or Cortex intervention.

2. **Default Threshold (`0.50`)**:
   - Strikes a balanced operating point on observed datasets (F1 = 0.9474), correctly escalating impossible tasks (TN = 3) while routing clear matches directly.

3. **Higher Thresholds (`>= 0.60`)**:
   - Increases the frequency of Cortex LLM escalations (up to 38.46% on labeled cases).
   - Cost: Higher average step latency and token usage, as borderline cases are handed over to the generative model.
   - Benefit: Restricts direct execution to highly unequivocal candidate matches.
